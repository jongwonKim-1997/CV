# Quantile 예측 기반 이상탐지: 수준 편차 대 점단위 오차

합성 데이터에서 "점단위 오차로는 안 잡히지만 horizon 간 상관을 고려하면 잡히는 이상"이
실제로 잡히는지 검증한 결과다.

- 창 수 N = 300, 시드 3개 (0, 1, 2), H = 32, T_ctx = 512, σ² = 0.5, 축소계수 λ = 0.05
- 점수 행 75,600개 (`results/scores.csv`), 지표 864행 (`results/metrics.csv`)
- 이상 케이스 7종 (N0, A0, A1, **A1'**, A2, A3, A4), 점수 12종
- 전 구간 재현 확인: 캐시를 지우고 두 번 실행해 `scores.csv`가 바이트 단위로 동일

## 실행 환경에 관한 두 가지 이탈

**1. keti 서버에서 실행하지 못했다.** 이 세션의 컨테이너는 egress가 443 HTTPS로만 제한돼
있어 SSH(포트 32306)가 나가지 않는다. 대조로 `github.com:22`도 동일하게 차단된다. 실험은
같은 컨테이너의 CPU 4코어에서 수행했다. 사양서의 "GPU 없으면 N을 줄여라" 조항은 적용하지
않았다. Chronos를 쓰지 못해 예측 비용이 무시할 수준이 됐고, N = 300과 시드 3개를 그대로
유지할 수 있었다 (과정별 셀당 1초 미만).

**2. Chronos-2와 chronos-bolt-small을 받지 못했다.** `chronos-forecasting 2.3.1`은 PyPI에서
정상 설치했고 설치된 패키지의 `Chronos2Pipeline.predict_quantiles(inputs, prediction_length,
quantile_levels)` 시그니처에 맞춰 래퍼를 작성했지만, 가중치 다운로드가 huggingface.co에서
막힌다.

```

chronos-bolt unavailable:  OSError: Can't load the configuration of 'amazon/chronos-bolt-small'
```

사양서는 이 경우 "oracle만으로 완료 후 명시"하라고 했다. 그렇게 하면 H5, H6를 학습된 모델에서
전혀 검증할 수 없으므로, **MLPQR**을 추가했다. 넓은 합성 패밀리(φ ~ U(0,1)에 25% 확률의
단위근, σ² ~ U(0.1,2), 절반에 임의 진폭·주기의 계절성)에서 pinball loss로 직접 학습한 뒤

"해석적이지 않은, 스스로 캘리브레이션 오차를 갖는 예측기"라는 역할만 수행한다. 다운로드가
가능한 환경에서 `run.py`를 그대로 실행하면 Chronos 경로가 자동으로 선택된다.

## 상수 정정이 아니라 방향 선택의 문제였다

사양서는 "이론값은 WN ≈ H, RW ≈ 1"이라 했고 H3은 T ≈ 0.7을 예측했다. 사양서가 정의한 A1과
방향 1을 그대로 쓰면 **RW의 n_eff는 1이 아니라 1.8641이다.**

z_h는 표준화된 오차 (x_{T+h} − x_T)/√(0.5h)이므로 corr(z_h, z_k) = min(h,k)/√(hk)이고,
corr(z_1, z_32)는 0.177까지 떨어진다. 완전상관이 아니다.

```
n_eff = 1ᵀR⁻¹1 = Σ_{h=1..H} (√h − √(h−1))²  =  1.864092   (H = 32)
```

수치 계산과 소수점 6자리까지 일치한다. 그런데 이건 단순한 상수 오류가 아니라
**두 개의 서로 다른 "상수 편차"가 있다는 뜻이다.**

| | 이상의 형태 | z 공간에서의 모양 | 맞는 방향 d |
|---|---|---|---|
| **A1** (사양서) | x_h = q50_h + 0.7·σ_h | z_h = 0.7, 평평 | **d = 1** |
| **A1'** (추가) | x_h = q50_h + 0.7·σ_1 | z_h = 0.7·σ_1/σ_h, 감쇠 | **d = 1/σ_h** |

A1은 z 공간의 상수라 편차가 σ_h에 비례해 커지는 경로이고, A1'은 x 공간의 상수라 시계열
자체의 단위로 고정된 변위다. σ_h가 h에 따라 변하면 둘은 다른 방향이며,
**WN에서만 일치한다**(σ_h가 평평하므로).

방향 d에 대해 일반화한 검정 통계량은 다음과 같다.

```
T_d = |dᵀR⁻¹z| / √(dᵀR⁻¹d),     n_eff_d = dᵀR⁻¹d   (d = σ_1/σ_h 로 정규화)
```

RW에서 d = σ_1/σ_h를 쓰면 Db가 평평해지고 브라운 이차형식이 첫 스텝만 남기므로
**n_eff_b = 1.000이 정확히 나온다.** 사양서가 겨냥했던 상수는 이것이다. 실측 1.002.

| 과정 | n_eff (d = 1) | n_eff_b (d = 1/σ_h) |
|---|---|---|
| WN | 32.000 | 32.000 |
| RW | 1.935 | **1.002** |
| AR1 | 6.887 | 3.922 |
| SEAS | 6.887 | 3.922 |

ORACLE에서 두 케이스를 두 방향으로 각각 재면 대각선이 이긴다. 굵은 값이 맞는 조합이다.

| 과정 | A1 · d=1 | A1 · d=1/σ | A1' · d=1 | A1' · d=1/σ |
|---|---|---|---|---|
| WN | **3.952** (1.000) | 3.952 (1.000) | 3.952 (1.000) | **3.952** (1.000) |
| RW | **0.972** (0.653) | 0.714 (0.513) | 0.514 (0.397) | **0.700** (0.497) |
| AR1 | **1.834** (0.950) | 1.815 (0.937) | 1.370 (0.834) | **1.384** (0.840) |
| SEAS | **1.834** (0.937) | 1.815 (0.934) | 1.370 (0.840) | **1.384** (0.850) |

괄호는 AUROC. RW에서 A1'을 맞는 방향으로 재면 **0.700**이 나오고(이론 0.7·√1 = 0.7),
틀린 방향으로 재면 0.514로 값도 해석도 잃는다. 반대로 A1을 맞는 방향으로 재면 0.972,
틀린 방향으로는 0.714다.

**이번 실험에서 얻은 설계 원칙: GLS의 방향은 잡으려는 이상의 형태와 맞춰야 한다.**
n_eff는 R만의 성질이 아니라 (R, d) 쌍의 성질이며, 방향을 정하지 않고 "유효 표본 수"를
말하는 것은 불완전하다.

한 가지 덧붙이면, RW/A1'을 맞는 방향으로 재도 AUROC는 0.497로 우연 수준이다.
이것은 실패가 아니다. n_eff_b = 1은 "유효 관측이 하나뿐"이라는 뜻이고, 0.7σ_1의 변위는
관측 하나로는 구별되지 않는다는 것이 랜덤워크 모델이 함의하는 정답이다.

## H1. 점단위 점수는 A1을 구별하지 못한다 (지지)

ORACLE / WN, N0 대 각 케이스의 AUROC:

| case | S_max | S_band | S_mean | S_gls_pert | S_chi2 | S_maha |
|---|---|---|---|---|---|---|
| A0 | 0.000 | 0.001 | 0.000 | 0.000 | **1.000** | 0.000 |
| A1 | **0.000** | **0.001** | 1.000 | **1.000** | 0.981 | 0.009 |
| A2 | 0.591 | 0.839 | 0.996 | **0.996** | 0.757 | 0.877 |
| A3 | **0.688** | 0.602 | 0.524 | 0.524 | 0.521 | 0.706 |
| A4 | 0.848 | 0.978 | 0.626 | 0.626 | **0.989** | 0.995 |

**"거의 구별되지 않는다"는 표현이 A1에는 부정확하다.** A1은 x_h = q50_h + 0.7σ_h로 잡음이
전혀 없는 결정적 경로다. 따라서 모든 h에서 z_h = 0.7이 되어 S_max = 0.7로 고정되는 반면,
정상 창의 max|z|는 평균 2.0 부근이다. A1이 정상보다 **일관되게 더 정상처럼 보이므로**
AUROC는 0.5가 아니라 0.000이 된다. 상단 꼬리를 보는 단측 탐지기로서 TPR@FPR5% = 0.000이고,
이 점에서 결론(못 잡는다)은 같지만 이유가 다르다. S_band도 같다. z = 0.7은 [q10, q90] 안에
있으므로 A1의 S_band는 항상 0이다.

**H1의 취지가 성립하는 케이스는 A2다.** A2는 잡음을 유지한 채 수준만 0.7σ₁ 이동시킨다.
WN에서 S_max AUROC = 0.591로 우연에 가깝고 TPR@FPR5% = 0.000인데, S_gls는 0.996 / 0.973이다.
**WN에서 A1에 대한 S_max 대 S_gls_pert의 AUROC 차이는 +1.000이고, A2에서는 +0.405다.**

### 기준선을 클리핑 없는 것으로 교체했다

21개 quantile 격자에서 PIT를 클리핑하면 |z| ≤ Φ⁻¹(0.995) = 2.576으로 포화된다. ORACLE 정상
창의 32.0%, MLPQR의 55.2%가 이 상한에 이미 걸려 있다. **이 상태로는 점단위 기준선이 부당하게
불리하다.** 특히 A3의 +4σ 스파이크는 상한에 완전히 포화돼(창의 98%) 크기 정보를 잃는다.

그래서 PIT를 거치지 않는 기준선을 추가했다.

```
S_max_raw = max_h |x_h − q50_h| / σ_h^model,   σ_h^model = (q75_h − q25_h) / 1.349
```

ORACLE 기준 AUROC 비교:

| 과정 / case | S_max (클리핑) | **S_max_raw** | S_gls_pert |
|---|---|---|---|
| WN / A3 스파이크 | 0.688 | **0.949** | 0.524 |
| AR1 / A3 | 0.706 | **0.831** | 0.505 |
| SEAS / A3 | 0.716 | **0.838** | 0.504 |
| RW / A3 | 0.610 | 0.618 | 0.502 |
| WN / A4 분산 증가 | 0.848 | **0.962** | 0.626 |
| WN / A2 수준 이동 | 0.591 | 0.753 | 0.996 |
| WN / A1 | 0.000 | **0.000** | 1.000 |
| WN / A1' | 0.000 | **0.000** | 1.000 |

**A1과 A1'의 결론은 클리핑과 무관하게 그대로다.** 0.000이 0.000으로 유지된다. A1은 z가 0.7로
고정된 결정적 경로라 클리핑 근처에 가지도 않기 때문이다. 반면 스파이크와 분산 증가에서는
클리핑이 기준선을 심하게 깎고 있었다. RW에서 개선이 작은 것은(0.610 → 0.618) 그 과정의
σ_h가 h와 함께 커져 스파이크가 애초에 상대적으로 작게 보이기 때문이다.

이하 H6의 비교는 모두 S_max_raw 기준이다.

## H2. WN에서 S_gls가 A1을 강하게 잡는다 (지지)

| 과정 | n_eff (λ=0.05) | S_gls 관측 | 0.7·√n_eff | AUROC | TPR@FPR5% |
|---|---|---|---|---|---|
| WN | 32.000 | **3.9525** | 3.9598 | 1.000 | 1.000 |
| AR1 | 6.887 | 1.8337 | 1.8371 | 0.950 | 0.333 |
| SEAS | 6.887 | 1.8337 | 1.8371 | 0.937 | 0.667 |
| RW | 1.935 | 0.9718 | 0.9736 | 0.653 | 0.000 |

관측값과 0.7·√n_eff가 네 과정 모두 0.004 이내로 일치한다. 남은 미세한 차이는 21점 격자
선형보간에서 z = 0.6987이 나오기 때문이며 (0.7이 아님), 이를 반영하면 오차는 사라진다.

AR1과 SEAS의 TPR@FPR5%가 AUROC에 비해 낮은 것은 실패가 아니라 **경계 효과**다. A1은
결정적 경로라 S_gls가 상수 1.8337인데, 캘리브레이션된 정상 창의 S_gls 95분위가 1.96 부근이다.
상수가 임계값 바로 아래에 놓여 시드에 따라 0 또는 1이 되고 평균이 1/3, 2/3으로 찍힌다.
분리 자체는 AUROC 0.95가 말해준다.

## H3. RW에서 S_gls는 잡지 않고, S_mean은 거짓 양성이다 (지지)

전반부는 명확하다. RW/A1의 S_gls = 0.9718이고 (정정된 목표 0.9736), TPR@FPR5% = 0.000이다.
모델이 함의하는 정답대로 잡지 않는다.

후반부는 **지표를 바꿔야 드러난다.** TPR@FPR5%는 임계값을 RW 자신의 정상 분포에서 잡으므로
독립 가정의 오류가 임계값 안으로 흡수돼 보이지 않는다. S_mean이 독립을 가정한다는 것은
곧 **명목 임계값 1.96을 쓴다**는 뜻이므로, 그 임계값에서의 실제 크기를 재야 한다.

ORACLE, 정상 창(N0)에서 점수가 1.96을 넘는 비율. 올바른 크기의 검정이면 0.05여야 한다:

| 과정 | S_mean | S_gls_pert | S_gls_pool | S_gls_emp |
|---|---|---|---|---|
| WN | 0.043 | 0.043 | 0.043 | 0.064 |
| RW | **0.687** | 0.051 | 0.051 | 0.056 |
| AR1 | **0.381** | 0.042 | 0.042 | 0.052 |
| SEAS | **0.378** | 0.044 | 0.044 | 0.057 |

같은 명목 임계값에서 A1을 "탐지"하는 비율:

| 과정 | S_mean | S_gls_pert |
|---|---|---|
| WN | 1.000 | 1.000 |
| RW | **1.000** | **0.000** |
| AR1 | **1.000** | 0.000 |
| SEAS | **1.000** | 0.000 |

**RW에서 S_mean의 거짓 양성률은 0.687로 명목 0.05의 13.7배**이고, 잡아서는 안 되는 A1을
100% 잡는다. S_gls는 크기 0.051을 정확히 지키면서 A1에 0.000으로 응답한다. H3이 주장한
대비가 그대로 나온다. AR1과 SEAS에서도 S_mean의 크기는 0.38로 무너진다. 독립 가정이
깨지는 모든 과정에서 같은 실패가 일어난다.

## H4. A0은 S_gls가 아니라 S_chi2의 대상이다 (지지)

ORACLE, 케이스 A0:

| 과정 | S_gls 평균 | S_gls AUROC | S_chi2 평균 | S_chi2 AUROC |
|---|---|---|---|---|
| WN | **0.0000** | 0.000 | 4.00 | **1.000** |
| RW | **0.0000** | 0.000 | 4.00 | **0.884** |
| AR1 | **0.0000** | 0.000 | 4.00 | **0.989** |
| SEAS | **0.0000** | 0.000 | 4.00 | **0.988** |

A0은 x_h = q50_h이므로 z ≡ 0이고 S_gls = |1ᵀR⁻¹0| / √(1ᵀR⁻¹1) = 0이 기계적으로 성립한다.
S_chi2는 |Σz² − H| / √(2H) = 32/8 = 4.00으로 이론값과 정확히 일치한다. **수준 검정은 분산
부족에 완전히 무감각하고, 대조군이 그것을 잡는다.** 두 검정이 직교한다는 뜻이며, 실무에서는
둘을 함께 돌려야 한다.

## H5. R_pert의 충실도 (부분 지지)

**ORACLE에서는 완벽하다.** 입력 섭동으로 얻은 ψ_h와 이론 ψ_h의 최대 절대 오차가 네 과정 모두
6.4e-15 이하다 (WN 0, RW 4.8e-14, AR1 3.3e-15, SEAS 6.4e-15). n_eff도 이론값과 정확히 같다.
사양서가 요구한 "코드 경로 검증"은 통과했다.

**학습된 모델에서는 창별 R_pert가 붕괴한다.** 이것이 이번 실험에서 가장 실무적으로 중요한
발견이다.

| 모델 / 과정 | n_eff 이론 | R_pert 창별 평균 | R_pert 창별 중앙값 | **R_pert pooled** | R_emp |
|---|---|---|---|---|---|
| ORACLE / WN | 32.00 | 32.00 | 32.00 | 32.00 | 35.43 |
| ORACLE / RW | 1.93 | 1.93 | 1.93 | 1.93 | 1.97 |
| ORACLE / AR1 | 6.89 | 6.89 | 6.89 | 6.89 | 7.47 |
| MLPQR / WN | 32.00 | **81.98** | 12.38 | 6.16 | 10.11 |
| MLPQR / RW | 1.93 | 2.13 | 2.11 | 2.09 | 1.87 |
| MLPQR / AR1 | 6.89 | **26.26** | 6.66 | 5.22 | 5.10 |
| MLPQR / SEAS | 6.89 | **26.43** | 9.91 | 8.37 | 5.64 |

창별 n_eff가 H = 32를 크게 넘는 것은 R에 체계적 음의 상관이 생겼다는 뜻이다. 원인을 추적했다.
MLPQR의 창별 ψ_1은 평균 0.205지만 표준편차가 0.292이고 [−0.619, 1.394] 범위에 퍼진다.
어떤 창은 lag 2~7에서 ψ가 −0.6까지 내려가며, 이런 음의 값 몇 개만으로 1ᵀR⁻¹1이 폭발한다
(최악 창에서 513). 섭동 크기 δ를 0.05σ에서 1.0σ까지 20배 키워도 ψ 추정이 거의 변하지
않으므로 (WN에서 0.2048 → 0.2132) **수치 잡음이 아니라 학습된 모델의 실제 국소 응답**이다.

### 평활이 답이지만, pooled는 배포에서 못 쓴다

ψ를 창들에 대해 평균내면 문제가 사라진다. 하지만 **그 pooled 추정은 과정 라벨을 알고 묶은
것이고 미래 창까지 들여다본다.** 배포 상황에서는 둘 다 없다. 그래서 배포 가능한 두 가지를
추가로 구현했다.

- **`S_gls_ema`** 창 축을 따라가는 인과적 EMA. 창 i에서 창 0..i만 사용한다(λ = 0.05, 반감기
  약 13창). 단일 시계열을 모니터링하는 상황에 그대로 대응한다. 단위 테스트에서 미래 창을
  바꿔도 과거 추정이 변하지 않음을 확인한다.
- **`S_gls_hybrid`** 창별 R_pert를 그 계열의 R_emp 쪽으로 축소(α = 0.5). R_emp는 정상 이력만
  있으면 추정되므로 역시 배포 가능하다. 둘 다 상관행렬이라 볼록결합의 대각은 1로 유지된다.

MLPQR 기준 결과다. `pooled`는 참고용 상한으로만 표시한다.

| 과정 | 이론 | 창별 R_pert | **EMA (인과)** | **hybrid** | R_emp | pooled (참고) |
|---|---|---|---|---|---|---|
| WN | 32.00 | 81.98 | **14.04** | **10.87** | 10.11 | 6.16 |
| AR1 | 6.89 | 26.26 | **6.26** | **5.89** | 5.10 | 5.22 |
| SEAS | 6.89 | 26.43 | **9.40** | **7.00** | 5.64 | 8.37 |
| RW | 1.93 | 2.13 | **2.09** | **1.98** | 1.87 | 2.09 |

명목 임계값 1.96에서의 실제 크기(정상 창, 목표 0.05):

| 과정 | 창별 R_pert | EMA | hybrid | R_emp | pooled |
|---|---|---|---|---|---|
| WN | 0.281 | **0.070** | 0.104 | 0.088 | 0.029 |
| AR1 | 0.309 | **0.160** | 0.166 | 0.143 | 0.131 |
| SEAS | 0.302 | **0.198** | 0.142 | 0.103 | 0.188 |
| RW | 0.116 | 0.117 | 0.102 | 0.094 | 0.116 |

A1 탐지 AUROC:

| 과정 | 창별 R_pert | EMA | hybrid | R_emp | pooled |
|---|---|---|---|---|---|
| WN | 0.725 | **0.834** | 0.831 | 0.856 | 0.865 |
| AR1 | 0.710 | **0.786** | 0.781 | 0.790 | 0.797 |
| SEAS | 0.669 | **0.732** | 0.725 | 0.733 | 0.733 |
| RW | 0.558 | 0.558 | 0.559 | 0.558 | 0.558 |

**인과적 EMA가 pooled 이득의 대부분을 회수한다.** WN에서 A1 AUROC는 0.725 → 0.834로,
pooled의 0.865에 근접한다. 명목 크기도 0.281 → 0.070으로 회복된다. AR1에서는 EMA의
n_eff 6.26이 pooled의 5.22보다 오히려 이론값 6.89에 가깝다. hybrid도 비슷한 수준이고,
SEAS처럼 EMA가 덜 듣는 곳에서는 hybrid가 더 낫다(크기 0.198 대 0.142).

`1ᵀR⁻¹1`은 소수의 작은 음의 비대각 성분에 극도로 민감하므로, **잡음 있는 예측기 위에서
창별 R을 그대로 쓰는 것은 어느 경우에도 권장할 수 없다.** 평활을 무엇으로 하느냐가 남는
선택이고, 여기서 검증한 두 가지는 모두 배포 가능한 형태다.

더 나은 선택지가 하나 남아 있다. ψ를 문맥 임베딩에서 예측하는 작은 회귀(proxy head)다.
창별 섭동은 잡음이 크고 EMA는 시간 축의 평활일 뿐이므로, 학습된 smoother가 원리적으로는
가장 낫다. 이번 실험은 그 필요성을 정량으로 뒷받침하지만 구현하지는 않았다.

**R_pert와 R_emp의 Frobenius 거리** (pooled 기준, 32×32 행렬):

| 과정 | ORACLE | MLPQR |
|---|---|---|
| WN | 1.271 | 4.415 |
| RW | **0.772** | 2.159 |
| AR1 | 1.346 | 1.777 |
| SEAS | 1.367 | 2.659 |

ORACLE에서 0.77~1.37은 500개 창에서 추정한 표본 상관행렬의 유한표본 잡음 수준이다.
MLPQR에서는 2~4배로 커진다. "거의 같다"고 하기는 어렵고, 같은 자릿수라는 정도가 정확하다.
**Chronos-2에서 검증하지 못한 부분이며, H5는 그만큼 미완이다.**

## H6. 스파이크와 수준 이동은 상호보완적이다 (지지)

케이스 A3(단일 시점 +4σ₁)의 AUROC:

| 모델 / 과정 | **S_max_raw** | S_max (클리핑) | S_band | S_mean | S_gls_pert | S_maha |
|---|---|---|---|---|---|---|
| ORACLE / WN | **0.949** | 0.688 | 0.602 | 0.524 | 0.524 | 0.706 |
| ORACLE / AR1 | **0.831** | 0.706 | 0.569 | 0.496 | 0.505 | 0.882 |
| ORACLE / SEAS | **0.838** | 0.716 | 0.572 | 0.498 | 0.504 | 0.883 |
| ORACLE / RW | **0.618** | 0.610 | 0.529 | 0.500 | 0.502 | 0.897 |

수준 검정은 A3에서 완전히 무력하다 (0.50, 우연 수준). H = 32에서 한 시점의 편차는 평균에
1/32로 희석되기 때문이다. 반대로 A1과 A1'에서는 점단위 점수가 0.000으로 무력하다.
클리핑 없는 기준선으로 바꾸면 대비가 오히려 더 선명해진다. WN에서 **0.949 대 0.524**다.
**두 계열은 서로 다른 부분공간을 본다.** S_maha가 두 경우 모두에서 중간 이상의 성능을 내지만 (A3에서 0.71~0.90),
A1에서는 0.009로 최악이다. 전체 Mahalanobis는 방향을 특정하지 않으므로 수준 이동에 대한
검정력을 잃는다. 실무에서는 S_gls(수준) + S_chi2(분산) + S_max(스파이크) 세 개를 병렬로
돌리는 구성이 타당하다.

## 학습 모델의 캘리브레이션과 ORACLE과의 괴리

**MLPQR의 예측구간은 체계적으로 좁다.** 정상 창에서 z의 분산이 1이어야 하는데:

| 과정 | h=1 | h=8 | h=16 | h=32 |
|---|---|---|---|---|
| ORACLE (WN) | 0.96 | 0.99 | 0.98 | 0.90 |
| MLPQR / WN | 1.30 | 1.12 | 1.13 | 1.00 |
| MLPQR / RW | 0.99 | 1.38 | 1.64 | 1.48 |
| MLPQR / AR1 | 1.27 | 1.72 | 1.83 | 1.39 |
| MLPQR / SEAS | 0.88 | 1.40 | 1.46 | 1.23 |

z 평균은 모두 0 근처로 편향은 없다. 깨진 것은 폭이며, **중간 horizon(h = 8~16)에서 가장
심하다** (분산 1.7~1.8, 즉 구간이 이론 대비 √1.8 = 1.34배 좁다). h = 1과 h = 32에서는 상대적으로
낫다.

원인은 zero-shot 식별 실패로 보인다. ψ 그림(`figures/psi_response.png`)이 이를 뒷받침한다.
MLPQR의 ψ는 모든 과정에서 학습 패밀리의 평균쪽으로 수축한다. WN에서 0이어야 할 ψ_1이 0.205,
RW에서 1이어야 할 ψ가 0.60~0.76, AR1에서 0.700이어야 할 ψ_1이 0.53이다. 모델이 문맥에서
φ를 정확히 식별하지 못하고 패밀리 평균으로 회귀한다. 조건부 분산도 같은 이유로 패밀리
평균 폭에 가까워지는데, 이 폭은 정상 AR1 다수를 포함하므로 단위근이나 백색잡음 케이스에는
너무 좁다. 512개 원시 입력을 받는 MLP가 자기상관을 계산하기 어렵다는 구조적 한계다.

**이것이 탐지기의 문제가 아님을 분리하기 위해** 별도의 정상 창 500개에서 학습한 horizon별
재캘리브레이션 z → (z − m_h)/s_h를 적용한 `MLPQR_CAL`을 추가했다. 캘리브레이션이 완벽한
모델에서는 항등변환이 된다.

| 지표 (MLPQR → MLPQR_CAL) | WN | AR1 | SEAS |
|---|---|---|---|
| 명목 크기 (S_gls_emp, N0) | 0.088 → 0.077 | 0.143 → **0.046** | 0.103 → **0.049** |
| A0의 S_chi2 AUROC | 0.944 → 0.964 | 0.484 → **0.902** | 0.493 → **0.736** |
| A1의 S_gls_pool AUROC | 0.865 → 0.874 | 0.797 → 0.772 | 0.733 → 0.733 |

재캘리브레이션은 **검정의 크기와 A0 탐지를 크게 복구**한다. AR1에서 S_chi2의 A0 AUROC가
0.484(우연)에서 0.902로 오르는 것이 대표적이다. 반면 A1의 수준 탐지력은 거의 변하지 않는다.
S_gls는 z를 상수배 해도 분자와 분모가 같이 변하는 방향으로 움직여 스케일 오차에 비교적
둔감하기 때문이다. **결론: ORACLE과 MLPQR의 괴리는 탐지기 논리가 아니라 예측기의 구간 폭에서
온다.** 수준 검정은 그 오차에 강건하고, 분산 검정(S_chi2)은 강건하지 않다.

MLPQR의 A1 AUROC가 ORACLE의 1.000에 못 미치는 잔여 격차(WN에서 0.865)는 재캘리브레이션으로
메워지지 않는다. 이는 ψ 수축(WN에서 0.205)이 R을 잘못 만들고 그것이 n_eff를 6.2로 낮춰
(이론 32) 검정력을 직접 깎기 때문이다. 즉 **예측기가 과정을 잘못 식별하면 탐지기는 그
잘못된 식별이 함의하는 답을 정확히 낸다.** H3에서 랜덤워크의 경우가 "실패가 아니라 정답"인
것과 같은 논리이며, 이 경우에는 모델이 틀렸으므로 대가를 치른다.

## 사양서 대비 구현상의 선택

1. **문맥을 케이스 간에 공유했다.** 사양서는 "과정 × 케이스별" N개 창을 말하지만, 이상은
   미래 구간에만 주입되므로 하나의 문맥과 하나의 예측에 6개 케이스를 붙이는 것이 옳다.
   예측 호출이 6분의 1로 줄고, 케이스 비교가 짝지어진 설계가 되어 검정력이 높아진다.
2. **λ = 0.05의 영향을 명시했다.** RW의 R은 거의 특이해서 5% 능선이 무시할 수 없다.
   n_eff가 1.8641 → 1.9346으로 움직인다. 단위 테스트는 λ = 0에서 해석적 목표를 고정하고,
   λ = 0.05에서 S_gls = 0.7·√n_eff 관계가 유지되는지를 따로 확인한다.
3. **A4의 문맥은 정상 과정에서 뽑았다.** 분산 증가는 미래 구간에만 적용한다. 예측기가
   오염된 문맥을 보면 이상 자체가 예측에 흡수되기 때문이다.
4. **추가한 것**: 케이스 A1'(x 공간 상수 편차), 방향 d = 1/σ_h를 쓰는 `S_gls_b`,
   클리핑 없는 `S_max_raw`, R 추정기 세 가지(`S_gls_pool` 참고용, `S_gls_ema` 인과적,
   `S_gls_hybrid`), `MLPQR_CAL`(재캘리브레이션), 명목 임계값 크기 지표.

## 권고하는 파이프라인 구성

이번 결과에서 직접 따라 나오는 구성이다.

1. **horizon별 재캘리브레이션을 표준 단계로 넣는다.** 정상 이력에서 m_h, s_h를 추정해
   z → (z − m_h)/s_h. 수준 검정은 구간 폭 오차에 강건하지만 분산 검정(S_chi2)은 그렇지 않고,
   재캘리브레이션 없이는 S_chi2가 우연 수준까지 떨어진다(AR1에서 0.484 → 0.902).
2. **R은 인과적으로 평활한다.** 창별 R_pert를 그대로 쓰지 않는다. 단일 계열의 EMA 또는
   R_emp 쪽 축소. 가능하면 문맥 임베딩에서 ψ를 예측하는 proxy head.
3. **세 검정을 병렬로 돌린다.** S_gls(수준) + S_chi2(분산) + S_max_raw(스파이크).
   서로 직교하며 어느 하나도 나머지를 대신하지 못한다.
4. **수준 검정의 방향을 명시한다.** 잡으려는 이상이 x 공간의 변위면 d = 1/σ_h,
   z 공간의 변위면 d = 1. 기본값으로 하나를 고르지 말고 두 방향을 함께 보고하는 편이 낫다.

## 남은 과제

**Chronos-2 검증이 본래 목표이며 아직 못 했다.** 이 환경에서 huggingface.co가 계속 403으로
막혀 있다(재확인 완료). MLPQR은 Chronos-2의 대용이 아니라 스트레스 테스트다. 512개 원시
입력을 받는 MLP는 in-context로 φ를 식별하지 못해 ψ가 패밀리 평균으로 수축했고, 그 결과가
n_eff 왜곡과 A1 검정력 저하다. Chronos-2의 in-context 식별력은 훨씬 강하므로 이 격차는
상당 부분 사라질 가능성이 있다.

HF 접근이 되는 환경에서 `run.py`를 그대로 돌리면 Chronos-2 경로가 자동 선택되고,
이번에 추가한 A1', `S_gls_b`, `S_max_raw`, EMA/hybrid R이 모두 함께 계산된다.
다시 채워야 할 표는 셋이다.

- 과정별·horizon별 캘리브레이션 표 (z의 평균과 분산)
- ψ_h 비교 그림 (Chronos-2의 ψ가 이론에 얼마나 붙는지)
- **창별 R_pert의 n_eff 분포** (붕괴가 Chronos-2에서도 일어나는지)

세 번째가 핵심 질문이다.
